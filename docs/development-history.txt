This is an experimental Linux receiver on beastmode's RTL8922AE PCI card
0000:0d:00.0. The full goal remains active: maximum practical bandwidth,
strong gapless qualification, and convenient application integration.

IMPLEMENTED
- Raw LA ring -> internal DMA ch5 -> owned PLE packet -> PCIe RX queue.
- Continuous acquisition until explicit stop, with no 60-second restart.
- Consuming 128 MiB host FIFO, 8 KiB packets, exclusive device ownership.
- Software ring overrun checks and an elapsed-poll guard to reject cases
  where a full ring wrap could be missed during process descheduling.
- SoapySDR driver=rtl8922; one RX channel, CS16 and CF32 formats.
- Native 5 MS/s (14-bit I/Q), 10 MS/s (12-bit I/Q) and 20 MS/s (8-bit I/Q).
  All three modes transfer 5 million 64-bit records/s (40 MB/s). Formats
  DMA12 and DMA14 pack two and four consecutive complex samples per record.
  The plugin preserves packed phase across arbitrary readStream boundaries.
- 2.5/1.25 MS/s through a continuous 191-tap Hamming FIR
  decimator. FIR history persists across packet and readStream boundaries.
- Packet sequence validation; loss surfaces as SOAPY_SDR_OVERFLOW.
- Sample-relative timestamps. There is no hardware time/PPS clock.
- Initial and live tuning accepts continuous frequencies at 2412..2472 MHz,
  or 2422..2462 MHz at 40 MS/s. getFrequencyRange follows the current mode.
  readSetting("rf_center") and readSetting("bb_offset") expose the chosen
  hardware center and digital offset. Invalid settings do not stop RX.
  Digital tuning does not widen or physically move the analogue passband;
  offset tuning has asymmetric RF edge coverage around the requested center.
  At decimated rates the FIR filters the translated signal before dropping
  samples. The receive response near RF filter edges is not yet qualified.
- Controls take priority over reader iterations. readStream respects its
  timeout while a setting change owns the lock. Same-hardware-center fine
  changes update only the oscillator; filter response settles naturally.
- Hardware setFrequency/setSampleRate serializes with readStream. It stops DMA,
  flushes the old sample/packet/filter state, configures the new setting,
  and restarts. The next read reports one SOAPY_SDR_OVERFLOW with HAS_TIME;
  subsequent reads contain only the new configuration. Software timestamps
  remain increasing using the measured host pause; timestamps across a
  change are approximate, not hardware sample timing. A change is therefore
  an explicit acquisition interruption, not a gapless retune. Unchanged
  settings are no-ops. Failed reconfiguration attempts restore old settings
  when possible and still report the interruption. The settled receiver
  remains continuous until another setting change or a detected overrun.
- Native modes: SMALLBW=1/selector2/DMA0 for 5 MS/s;
  SMALLBW=2/selector3/DMA12 for 10 MS/s;
  SMALLBW=0/selector4/DMA14 for 20 MS/s. Selecting only one phase of HT20
  at 5 million records/s aliases wider signals; decoding all four phases
  supplies the full 20 MS/s waveform instead.

RUN ON THE VERIFIED HOST
Place run-receiver.sh in /home/plaing/rtl8922-iq-research/soapy.
From that directory, a bounded headless GNU Radio test is:
  sudo -n bash run-receiver.sh env \
    SOAPY_SDR_PLUGIN_PATH=/home/plaing/rtl8922-iq-research/soapy/build-distro \
    PYTHONPATH=/usr/lib/python3/dist-packages \
    /usr/bin/python3 gnuradio-check.py

The PYTHONPATH is intentionally limited to this process: the distribution
GNU Radio extension needs NumPy1, while the host's normal Python resolves
NumPy2. No global NumPy package was downgraded.

For native ABI0.8-3 probe, use:
  sudo -n bash run-receiver.sh env \
    SOAPY_SDR_PLUGIN_PATH=/home/plaing/rtl8922-iq-research/soapy/build \
    /usr/local/bin/SoapySDRUtil --probe=driver=rtl8922

An application uses device arguments driver=rtl8922 and antenna PATH1.
For the ten-minute-tested 40 MS/s configuration use:
  driver=rtl8922,experimental40=1,producer_scheduler=deadline
Select 40,000,000 samples/s and an RF center of 2422..2462 MHz in 5 MHz steps.
The plugin requests SCHED_DEADLINE only for its capture worker, with runtime
950 us, deadline 1000 us and period 1000 us. The reader retains normal
scheduling. Failure to obtain the requested policy fails activation and
prints its reason. Root/CAP_SYS_NICE is needed. No global scheduler settings
are changed; thread exit releases the reservation. Observed producer CPU
usage was approximately one core, not a measured hard 95% CPU ceiling.
producer_scheduler=normal remains the default. Set RTL8922_TRACE=1 to print
producer timing/overrun counters on each deactivation. The kernel counts
maximum polling and mutex-yield pauses and distinguishes four overrun sites.
Policy reference: https://docs.kernel.org/scheduler/sched-deadline.html
Currently root is required for debugfs/register access and iw tuning.
The wrapper requires that the Realtek card be unbound and its temporary
firmware/config paths not already exist; it refuses to overwrite them.
It leaves wired networking and unrelated services alone. No persistent
system service or installed kernel module has been created.

40 MS/s DEVELOPMENT FOLLOW-UP
- An optional packet pipeline now overlaps next-buffer allocation and
  previous-completed-packet dispatch with the current internal DMA copy.
  Packet-header writes and changes to indirect memory selector0xc04 MUST
  wait until the current copy completes. Moving those operations into the
  active DMA period caused reduced writer progress and invalid continuity.
- With header writes deferred, a1second40MS/s experiment transferred
  79,994,880raw bytes in9765packets, zero FIFO drops/sequence gaps, and all
  last30blocks matched the frozen LA ring byte for byte. Native40MHz tone
  appeared at~111.7kHz. Log:output/rtl8922-pipeline40-defer-header-run.json.
- One2second CS16+CF32 plugin test also passed at40MS/s. Longer attempts
  failed because the LA engine entered its completed state. Extending the
  post-trigger interval to4.16seconds extended operation correspondingly,
  establishing an unintended trigger rather than a host FIFO overflow.
